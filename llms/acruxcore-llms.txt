# AcruxCore

> AcruxCore is an open-source platform for teams building on LLMs: version your prompts, route every model call through one OpenAI-compatible gateway, trace what happened, catalog the tools your models can call, evaluate the result, and read an audit trail of every change a person made. Apache 2.0, self-hostable, with published SDKs for Python and TypeScript.

The gateway sits in the request path, so a trace records the request that was actually sent rather than a copy reported alongside it. That is the design decision most of these pages come back to.

This documentation is Apache 2.0 and free to use, quote, and train on. Pages are written to be read in full: guides and tutorials each carry the real commands and the real output from a run against a live server, and every benchmark links the script that produced its numbers.

The product site is https://acruxcore.com. The source is at https://github.com/AcruxCore/AcruxCore.

## Guides

One AcruxCore capability per page, start to finish, with the exact requests and the real output.

- [Create a tool](https://docs.acruxcore.com/docs/guides/create-a-tool): Put a tool in the catalog two ways — a decorated function whose code owns the definition, or a catalog version your code only implements — and pick the owner that fits the project.
- [Evaluate a prompt against a dataset](https://docs.acruxcore.com/docs/guides/evaluate-a-prompt): Build a dataset from real user feedback or a CSV/JSON test set, run an experiment that sweeps prompt versions and models, and read the run report.
- [Invite a teammate to your team](https://docs.acruxcore.com/docs/guides/invite-a-teammate): Create a single-use invite link, choose the role it grants, and email it straight to a new teammate to get them into your AcruxCore team.
- [Route your app's LLM calls through the gateway](https://docs.acruxcore.com/docs/guides/route-calls-through-the-gateway): Add a provider credential, register a model, test it in the Playground, and call the OpenAI-compatible gateway from curl, the SDK, or the OpenAI client.
- [Trace and inspect an LLM call](https://docs.acruxcore.com/docs/guides/trace-an-llm-call): Every gateway call is traced automatically. Inspect spans, read dashboards, and report your own custom spans from app code with the SDK.
- [Version a prompt and ship it to production](https://docs.acruxcore.com/docs/guides/version-a-prompt): Create a prompt, commit versions, promote an alias to production, and render it from your app — the full prompt lifecycle in AcruxCore.
- [Chat, stream, and collect feedback with the SDK](https://docs.acruxcore.com/docs/guides/use-the-sdk-for-chat-and-feedback): Call the gateway from the SDK with chat() and streaming, run a traced tool-calling loop, then read traces back and record feedback — in Node and Python.
- [Connect a tool to a prompt](https://docs.acruxcore.com/docs/guides/connect-a-tool-to-a-prompt): Bind a catalog tool to a prompt by choosing the tool alias it follows, give one prompt alias its own tools, and see when the tool's code changed underneath you.
- [Improve a prompt from feedback](https://docs.acruxcore.com/docs/guides/improve-a-prompt-from-feedback): Turn replies your team disagreed with into candidate rewrites of your production prompt, score them against what is live, and promote the one that earns it.
- [Manage team roles and permissions](https://docs.acruxcore.com/docs/guides/manage-team-roles-and-permissions): See who's on your team, change an existing member's role, and remove their access — the three actions inviting a teammate doesn't cover.
- [Use conditional logic in prompt templates](https://docs.acruxcore.com/docs/guides/use-conditional-logic-in-prompt-templates): Write Jinja2-style {% if %} conditionals and {% for %} loops inside a prompt template, rendered by AcruxCore's nunjucks-based engine.
- [Using sessions and traces](https://docs.acruxcore.com/docs/guides/using-sessions-and-traces): Group related prompt calls into a session, follow one call into its trace, leave feedback, and jump back to the prompt that produced it.
- [Call a prompt's tools from the SDK](https://docs.acruxcore.com/docs/guides/call-a-prompts-tools-from-the-sdk): Every way to run the tools bound to a prompt from the SDK — the two-line shortcut, the loop by hand, and one raw completion — streaming or not.
- [Diff, export, and import your prompt library](https://docs.acruxcore.com/docs/guides/diff-export-and-import-your-prompt-library): Read a unified diff between two prompt versions, export one as a portable JSON file, and re-import it — including what import does and does not preserve.
- [Evaluate a prompt with conversation history](https://docs.acruxcore.com/docs/guides/evaluate-a-prompt-with-conversation-history): Carry a session's prior turns into a dataset example so a run, the judge, and the optimizer see the same conversation the model actually answered in.
- [Read the team audit trail](https://docs.acruxcore.com/docs/guides/read-the-team-audit-trail): See every recorded change in your team — API keys, members, gateway, secrets, prompts and tools — and filter it down to the one action you need to account for.
- [Scope access with virtual keys](https://docs.acruxcore.com/docs/guides/scope-access-with-virtual-keys): Create a gateway key restricted to one model, a rate cap, and a cache TTL, so a leaked key can't spend outside its job.
- [Tag and filter traces](https://docs.acruxcore.com/docs/guides/tag-and-filter-traces): Attach tags and metadata to traces, filter them by tag or metadata key/value, and discover what tags your team is using.
- [Look up the traces a prompt version produced](https://docs.acruxcore.com/docs/guides/look-up-the-traces-a-prompt-version-produced): Find every trace a specific prompt version powered, from the Versions tab or the API, and know when an empty result is expected.
- [Manage prompts via the SDK](https://docs.acruxcore.com/docs/guides/manage-prompts-via-the-sdk): Create a prompt, commit versions with templated messages, diff, promote aliases, export/import, and delete — the full lifecycle through curl or the SDK, no dashboard required.
- [Score live traffic with an evaluation rule](https://docs.acruxcore.com/docs/guides/score-live-traffic-with-an-evaluation-rule): Create a standing rule that judges matching production gateway calls automatically, with no dataset and no manual run.
- [Set spend limits with gateway budgets and rate limits](https://docs.acruxcore.com/docs/guides/set-spend-limits-with-gateway-budgets-and-rate-limits): Cap spend team-wide or per key by day, week, month, or total, and pair it with a request-rate cap — then prove both actually reject a call before it costs anything.
- [Version and track a tool](https://docs.acruxcore.com/docs/guides/version-and-track-a-tool): Commit a second tool version, move staging ahead of production, read real call volume, error rate and latency, and retire a tool you no longer call.
- [Evaluate a prompt that reads an image](https://docs.acruxcore.com/docs/guides/evaluate-a-prompt-that-reads-an-image): Store a prompt with an image part, fill the image from a dataset example, run it on several vision models, and read the scores a judge gives after looking at the same image.
- [Report a tool failure from your own code](https://docs.acruxcore.com/docs/guides/report-a-tool-failure-from-your-own-code): A tool call can fail while the HTTP status says 200. Return a ToolResult from your tool and the failure is recorded as a red span instead of a green one.
- [Retries and fallbacks: what the gateway does when a provider call fails](https://docs.acruxcore.com/docs/guides/automatic-model-fallbacks): Three separate things retry a failing LLM call, and each is set in a different place. Configure all three, then read two real traces to see which one fired.
- [Store prompts and tools via the API](https://docs.acruxcore.com/docs/guides/store-prompts-and-tools-via-api): Save a prompt and its tools over the REST API, confirm them in the dashboard, then fetch and stream them from the SDK.
- [View trace analytics](https://docs.acruxcore.com/docs/guides/view-trace-analytics): Read aggregate volume, error-rate, token, cost, and latency metrics over every trace your team has recorded, grouped by day, model, session, or prompt version.
- [Configure trace payload capture](https://docs.acruxcore.com/docs/guides/configure-trace-payload-capture): Read and toggle your team's default for whether a trace's request/response bodies get stored on ingest, and override that default for a single request.
- [Send an image to a model](https://docs.acruxcore.com/docs/guides/send-an-image-to-a-model): Pass an image to a vision model through the gateway, either as a link or as a file, and check what the trace stores.
- [Write a custom judge prompt](https://docs.acruxcore.com/docs/guides/write-a-custom-judge-prompt): Grade experiment runs and evaluation rules with your own rubric, including examples that have no criteria, and see exactly what the judge model receives.
- [Send OTel traces to AcruxCore with the SDK helper](https://docs.acruxcore.com/docs/guides/send-otel-traces-with-the-sdk-helper): Wire any OpenTelemetry-instrumented app to AcruxCore's OTLP endpoint in one call with register() — a bare pipeline, one framework, several frameworks, and session grouping, in Python or Node.

## Benchmarks and comparisons

Measured write-ups and hands-on comparisons against other LLM-ops platforms. Every number comes from a script committed to the repository, and every competitor screenshot from a real run on that competitor.

- [Braintrust alternative: what changes when the platform runs your tool code](https://docs.acruxcore.com/blog/acruxcore-vs-braintrust): The same prompt and the same tool run on both platforms, with real screenshots. A tool was pushed and executed on Braintrust's runtime, and running their Python SDK turned up a templating bug.
- [Laminar alternative: SQL over traces vs a prompt gateway](https://docs.acruxcore.com/blog/acruxcore-vs-laminar): A Laminar alternative tested hands-on — one example on self-hosted Laminar and AcruxCore, with real screenshots from both and a 100-round latency benchmark.
- [Full-cycle latency across six LLM-ops platforms, measured against real OpenAI](https://docs.acruxcore.com/blog/full-cycle-latency-benchmark): We timed prompt-fetch-plus-completion, not just the model call, across Opik, MLflow, Langfuse, Helicone, Phoenix, and AcruxCore's gateway and gateway-free BYOK modes, against a real OpenAI baseline — then ran it four times to see what's stable and what isn't.
- [MLflow alternative: two gateways, one with guardrails](https://docs.acruxcore.com/blog/acruxcore-vs-mlflow): Considering an MLflow alternative for LLM work? We timed the same prompt through both gateways — MLflow's added +135 to +225 ms, ours +21 to +43 ms.
- [Helicone alternative: two request-path proxies, measured](https://docs.acruxcore.com/blog/acruxcore-vs-helicone): Weighing a Helicone alternative? Both sit in the request path. We rebuilt one prompt on each, and timed 300 benchmark rounds through both gateways.
- [Opik alternative: guardrails, PII and online evaluation](https://docs.acruxcore.com/blog/acruxcore-vs-opik): An Opik alternative tested hands-on — one prompt rebuilt on self-hosted Opik and AcruxCore, with real screenshots, an SDK trace and a latency benchmark.
- [Arize Phoenix alternative: OTel tracing vs a gateway](https://docs.acruxcore.com/blog/acruxcore-vs-phoenix): An Arize Phoenix alternative tested hands-on — one prompt rebuilt on Phoenix and AcruxCore, with real screenshots, an SDK trace and a latency benchmark.
- [Langfuse alternative: org hierarchy vs a flat team](https://docs.acruxcore.com/blog/acruxcore-vs-langfuse): A Langfuse alternative tested hands-on — the same prompt rebuilt and run on both, with real screenshots, an SDK trace and a measured latency benchmark.
- [Exact-match gateway caching: latency and cost saved](https://docs.acruxcore.com/blog/exact-match-gateway-caching): We measured the gateway's exact-match response cache against the calls it's built for — a ~100x latency drop on a hit, and zero cost, from a live run.
- [One gateway, three providers: request shapes compared](https://docs.acruxcore.com/blog/one-gateway-three-providers): The same chat request, translated into Anthropic, Gemini, and OpenAI's own shapes by the gateway's adapters — headers, params, and tool defs, side by side.

- [LangChain vs AcruxCore SDK: the same tool-calling agent](https://docs.acruxcore.com/blog/tool-agent-sdk-langchain-vs-acruxcore): We rewrote the same tool-calling agent with LangChain's create_agent and the AcruxCore SDK's run_tool_loop, ran both live, and compared the code and traces.
- [Tool-call traces: LangSmith vs AcruxCore](https://docs.acruxcore.com/blog/tool-calling-traces-langsmith-vs-acruxcore): We built the same weather tool twice — a traced Python function on LangSmith, a versioned Tool Catalog entry on AcruxCore — ran both live, and counted the code.
- [A hands-on walkthrough of the AcruxCore dashboard](https://docs.acruxcore.com/blog/acruxcore-hands-on-walkthrough): A step-by-step walkthrough of prompt versioning, tracing, and evaluation in AcruxCore — the baseline for our competitor comparisons.

- [Hands-on with LangSmith: a real walkthrough](https://docs.acruxcore.com/blog/langsmith-hands-on-walkthrough): A step-by-step, screenshot-backed walkthrough of creating a prompt, running a trace, and building an eval dataset in LangSmith's hosted product.
- [A hands-on walkthrough of PromptLayer](https://docs.acruxcore.com/blog/promptlayer-hands-on-walkthrough): Logging into hosted PromptLayer, creating and versioning a prompt, running it, and checking what its trace view and evaluation tooling actually show.
